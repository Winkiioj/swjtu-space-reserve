## 1. 项目概述

### 1.1 项目背景
西南交通大学拥有众多教室资源和图书馆座位资源，传统的教室借用和图书馆座位预订方式存在以下问题：
- 信息不透明，学生难以了解教室的实时可用情况
- 流程繁琐，需要多次往返办公室
- 资源利用效率低下

### 1.2 项目目标
建立一个基于微信小程序的教室租借和图书馆座位预订系统，为西南交通大学师生提供：
- 快捷便利的教室租借服务
- 透明化的资源展示
- 智能化的资源分配管理
- 降低行政管理成本

### 1.3 项目范围
本需求分析文档仅关注**借教室模块**的功能需求，涵盖用户端的所有教室租借业务流程。

## 2. 借教室模块功能概述

### 2.1 模块目标
为西南交通大学师生提供在线便捷的教室租借服务，包括：
- 教室资源的查询和筛选
- 个性化租借需求的提交
- 租借申请状态的跟踪
- 租借记录的管理

### 2.2 核心业务价值
- **用户视角**：快速找到满足需求的教室，简化租借流程
- **学校视角**：提高教室资源的利用率和管理效率
- **系统视角**：自动化处理申请，减少人工干预

## 3. 系统业务流程

### 3.1 主业务流程（用例图）
```
交大师生登录 
    ↓
主页面展示
    ↓
选择"借教室"功能
    ↓
提交租借需求（事由、容量、时间）
    ↓
系统筛选并展示可租借教室列表
    ↓
个性化需求查询（楼层、位置、设备等）
    ↓
选择教室并确认租借申请
    ↓
提交申请至管理员审核
    ↓
等待系统/管理员回应
    ↓
收到审核结果（批准/拒绝）
```

### 3.2 详细业务流程说明

#### 3.2.1 用户登录
- **前置条件**：用户拥有有效的西南交通大学教师/学生身份
- **流程**：
  1. 用户打开微信小程序
  2. 授权微信登录或输入学号/密码
  3. 系统验证用户身份
  4. 登录成功，进入主页面

#### 3.2.2 浏览主页面
- **功能展示**：
  1. 系统公告/通知
  2. 快速操作入口（借教室、借座位）
  3. 个人租借记录摘要
  4. 个人信息区域

#### 3.2.3 发起租借申请
- **用户操作**：
  1. 点击"借教室"入口
  2. 进入需求填表页面
  3. 输入基本需求：
     - 租借事由（会议、培训、学习、其他）
     - 所需容量（人数）
     - 租借讲次（按讲次划分时间段）
     - 租借日期
  4. 点击"查询教室"按钮

#### 3.2.4 系统筛选与展示
- **系统处理**：
  1. 根据提交的需求条件筛选教室
  2. **筛选条件**：
     - 容量满足需求
     - 指定讲次未被占用
     - 不与已排课程冲突
     - 教室状态为"可用"
  3. 返回满足条件的教室列表（包含教室号、容量、位置等基本信息）

#### 3.2.5 个性化需求查询
- **用户操作**：
  1. 在教室列表中选择教室
  2. 查看教室详细信息：
     - 教室编号、名称
     - 所在楼栋和楼层
     - 容纳人数
     - 设备配置（投影仪、白板、音响等）
     - 周围配套设施
     - 交通便利性
  3. 支持进一步筛选：
     - 按楼层筛选
     - 按设备需求筛选
     - 按位置偏好筛选

#### 3.2.6 提交租借申请
- **用户操作**：
  1. 确认选择的教室
  2. 输入更多申请信息：
     - 租借事由详细说明
     - 联系方式
     - 其他特殊需求
  3. 确认申请信息
  4. 提交申请
- **系统处理**：
  1. 记录申请信息
  2. 生成申请单号
  3. 申请状态设为"待审核"
  4. 通知管理员审核

#### 3.2.7 等待系统回应
- **用户操作**：
  1. 进入"我的申请"页面
  2. 查看申请状态：
     - 待审核：管理员正在审核
     - 已批准：租借申请已被批准，可以使用教室
     - 已拒绝：租借申请被拒绝，显示拒绝原因
  3. 可查看详细申请信息
  4. 收到推送通知（审核结果）

## 5. 非功能需求

### 5.1 性能需求
- **响应时间**：
  - 页面加载时间 ≤ 2秒
  - 教室搜索结果返回时间 ≤ 1秒
  - 申请提交完成时间 ≤ 2秒

- **并发处理**：
  - 系统支持至少500个并发用户
  - 在高峰期（选课期间）不出现明显卡顿

### 5.2 可用性需求
- **系统可用性**：≥ 99.5%（全年计算）
- **运维响应**：系统异常4小时内恢复
- **用户界面**：符合微信小程序设计规范，操作直观

### 5.3 安全需求
- **身份认证**：
  - 必须通过西南交通大学统一身份认证
  - 支持微信授权安全登录

- **数据加密**：
  - 传输层：HTTPS加密传输
  - 存储层：敏感数据加密存储

- **权限控制**：
  - 用户只能查看/操作自己的申请
  - 不同角色拥有不同权限

- **防护措施**：
  - 防止SQL注入
  - 防止XSS攻击
  - 速率限制（防止刷屏/恶意请求）

### 5.4 可维护性需求
- **代码规范**：遵循代码编码规范
- **文档完整性**：提供详细的代码注释和使用文档
- **日志记录**：记录所有关键操作和异常

### 5.5 兼容性需求
- **支持版本**：
  - 微信小程序基础库版本 ≥ 2.18.0
  - 支持iOS和Android平台

- **浏览器兼容**：无（小程序环境）

### 5.6 可扩展性需求
- **模块化设计**：前后端均采用模块化架构
- **接口标准化**：RESTful API设计规范
- **数据库设计**：支持后续功能扩展

## 9. 约束条件

### 9.1 业务约束
- **教室资源限制**：
  - 同一教室同一讲次只能被一个申请占用
  - 不能与课表中的已排课程冲突
  
- **时间限制**：
  - 租借时间按讲次划分（8:00-9:50, 10:00-11:50等）
  - 最多提前30天申请

- **审核流程**：
  - 管理员必须在24小时内审核申请
  - 拒绝申请必须给出原因

- **用户限制**：
  - 黑名单用户不能提交申请
  - 有违规记录的用户可能被限制申请

### 9.2 技术约束
- **开发环境**：
  - 前端：微信小程序
  - 后端：Java 或 Node.js
  - 数据库：小程序云开发
  - IDE：VS Code
  - 版本控制：Git + GitHub

- **第三方依赖**：
  - 学校统一身份认证系统API
  - 微信官方API

## 10. 风险分析

### 10.1 技术风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|--------|
| 教室数据导入不完整 | 中 | 中 | 数据验证机制，导入前检查 |
| 实时性不足 | 中 | 高 | 缓存策略，定时刷新 |
| 并发冲突 | 低 | 高 | 数据库事务控制，分布式锁 |
| 系统崩溃 | 低 | 高 | 异常处理，监控告警 |

### 10.2 业务风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|--------|
| 用户操作误解 | 中 | 中 | 完善帮助文档，提示信息 |
| 管理员审核延迟 | 中 | 中 | SLA约定，系统提醒 |
| 恶意申请 | 中 | 中 | 黑名单机制，审核过滤 |

### 10.3 风险缓解计划
- 定期进行系统测试和压力测试
- 建立完善的异常处理和日志机制
- 制定清晰的操作规范和FAQ
- 与管理部门协调工作流程和SLA
