## 1. 引言

### 1.1 编写目的

本文档旨在对"教室租借与图书馆座位预定系统"中的管理员空间资源管理模块进行详细的需求分析，明确该模块的功能范围、业务流程、数据模型及非功能性要求，为后续的设计、开发与测试工作提供依据。本文档的预期读者包括：项目管理人员、系统设计人员、开发人员、测试人员及相关利益相关方。

### 1.2 项目背景

随着西南交通大学校园信息化建设的不断深入，传统的教室借用和图书馆座位管理方式已无法满足师生日益增长的需求。目前，教室租借和图书馆座位预定依赖线下人工管理，存在效率低、信息不透明、资源利用率不高等问题。为此，项目组决定开发一套"教室租借与图书馆座位预定系统"，基于微信小程序平台，为师生提供便捷的在线教室租借申请和图书馆座位预约服务，同时为管理人员提供高效的审核与资源管理工具。

本人负责的管理员空间资源管理模块，是整个系统的管理与控制核心，承担着资源初始化、申请审核、状态维护等关键职能，是保障系统正常运转的基石。

### 1.3 术语与缩略语

| 术语 | 含义 |
|------|------|
| 讲次 | 教室租借的时间单位，每天分为 13 个讲次（第 1 讲至第 13 讲） |

## 2. 项目概述

### 2.1 系统整体说明

本系统是基于微信小程序平台的教室租借与图书馆座位预定系统，主要面向两类用户：

| 角色 | 功能 |
|------|------|
| **普通用户（师生）** | 浏览教室信息、提交教室租借申请、预定图书馆座位、查看个人申请记录 |
| **管理员** | 管理教室与座位资源、审核租借申请、导入基础数据、维护系统运行状态 |

### 2.2 管理员模块定位

管理员空间资源管理模块是整个系统的管理与控制中枢，承担以下核心职责：

- **数据初始化**：导入教室、课表、座位等基础数据，完成系统初始化的数据准备
- **资源管理**：维护教室及图书馆座位信息，管理教室各讲次和座位各时段的状态
- **申请审核**：查看并处理用户提交的教室租借申请，执行通过或拒绝操作
- **系统维护**：通过定时任务完成状态矩阵的轮转、过期申请的状态更新等日常维护工作

### 2.3 用户角色定义

| 角色 | 职责描述 | 核心用例 |
|------|---------|---------|
| 系统管理员 | 负责系统基础数据导入、教室/座位信息管理 | 数据初始化、资源状态维护 |
| 审核管理员 | 负责处理用户的教室租借申请 | 查看待审核列表、审核通过/拒绝 |
| 运维管理员 | 负责系统日常维护和定时任务管理 | 监控系统运行、执行数据维护 |

> **注**：当前系统版本中以上三个角色合并为一个管理员账号，通过 Users 集合中的 `identity` 字段标识（值为 `"admin"`）。

## 3. 功能需求

### 3.1 管理员登录认证

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-001 |
| **名称** | 管理员登录认证 |
| **优先级** | 高 |
| **前置条件** | 管理员已获取有效的用户ID，且在 Users 集合中 identity 字段被标记为 "admin" |
| **触发事件** | 管理员通过 Logo 连点 3 次进入管理员登录页面 |
| **基本流程** | ① 管理员输入用户ID；② 系统调用 getUserByID 云函数查询用户信息；③ 验证用户身份是否为管理员；④ 验证通过，跳转至管理面板；否则跳转至普通用户首页 |
| **后置条件** | 系统全局保存 userRole 和 currentUserID 信息，用于后续操作的身份校验 |
| **备选流程** | 用户ID不存在 → 提示"用户不存在"；非管理员身份 → 跳转至普通用户首页 |

### 3.2 数据初始化

#### 3.2.1 教室信息导入

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-002 |
| **名称** | 导入教室信息 |
| **优先级** | 高 |
| **输入** | 教室基础数据列表（所属教学楼、教室编号、容纳人数、教室描述等） |
| **基本流程** | ① 管理员在"数据导入"页面点击"导入教室"按钮；② 系统调用 importClassrooms 云函数；③ 校验当前用户的管理员身份；④ 逐条创建 Classrooms 集合文档；⑤ 为每个教室初始化本周/下周状态矩阵（5天×13讲次的零矩阵） |
| **后置条件** | Classrooms 集合中存入教室数据，状态矩阵初始化为全0（全部可用） |

#### 3.2.2 课表信息导入

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-003 |
| **名称** | 导入当学期课表信息 |
| **优先级** | 高 |
| **输入** | 当学期课程安排数据（教室、星期、起始讲次、结束讲次等） |
| **基本流程** | ① 管理员点击"导入课程"按钮；② 系统调用 importCourses 云函数；③ 校验当前用户的管理员身份；④ 查找对应教室文档；⑤ 将课表占用时段在教室状态矩阵中标记为 1（课程占用） |
| **后置条件** | 教室状态矩阵中对应课程时段被标记为 1，不可再被租借申请 |
| **业务规则** | 课表优先级高于教室租借申请，课表占用的时间段不允许被租借 |

#### 3.2.3 教室状态初始化

在导入课表后，教室的 thisWeekStatusMatrix 和 nextWeekStatusMatrix 即完成初始化。其中：
- `0` = 可用（空闲）
- `1` = 课程占用
- `2` = 租借占用

初始化阶段仅设置 0 和 1，2 由审批通过后自动设置。

#### 3.2.4 图书馆座位信息导入

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-004 |
| **名称** | 导入图书馆座位信息 |
| **优先级** | 高 |
| **输入** | 图书馆座位基础数据（所属区域、座位编号、座位类型等） |
| **基本流程** | ① 管理员点击"导入座位"按钮；② 系统调用 importSeats 云函数；③ 校验当前用户的管理员身份；④ 逐条创建 Seats 集合文档；⑤ 初始化当日/次日状态矩阵（13小时段的零数组） |
| **后置条件** | Seats 集合中存入座位数据，状态矩阵初始化为全 0（全部可预订） |

> **时间单位说明**：图书馆座位以小时为时间段单位（区别于教室的讲次单位），每天划分为 13 个时段（08:00-21:00）。

### 3.4 教室租借审核

#### 3.4.1 待审核列表

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-006 |
| **名称** | 查看待审核申请列表 |

| **展示字段** | 申请人姓名、教室名称、使用日期、星期、申请讲次、申请理由 |
| **交互** | 点击任一卡片跳转至审核详情页，携带申请ID |

#### 3.4.2 审核详情查看

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-007 |
| **名称** | 审核详情查看 |
| **优先级** | 高 |
| **描述** | 查看单条教室租借申请的完整信息，包括申请人详情、教室信息及替代方案推荐 |
| **基本流程** | ① 管理员从待审核列表点击卡片进入详情页；② 系统调用 getApplicationDetail 云函数；③ 校验管理员身份；④ 查询申请详情、申请人信息（含联系电话）、教室信息；⑤ 智能推荐替代教室（容量≥原教室且在相同时段空闲的教室，最多5个） |

#### 3.4.3 审核通过

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-008 |
| **名称** | 审核通过申请 |
| **优先级** | 高 |
| **描述** | 管理员同意该教室租借申请 |
| **基本流程** | ① 管理员在详情页点击"通过"按钮；② 系统调用 approveApplication 云函数；③ 校验申请仍处于待审核状态；④ 再次校验所选讲次是否仍然可用（并发冲突检测）；⑤ 将申请状态设置为 1（已通过）；⑥ 将教室状态矩阵对应时段标记为 2（租借占用） |
| **异常处理** | 若所选讲次已被占用或发生并发修改，返回 409 状态码，提示管理员刷新重试 |
| **后置条件** | 教室状态矩阵更新，申请状态变为"已通过" |

#### 3.4.4 审核拒绝

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-009 |
| **名称** | 审核拒绝申请 |
| **优先级** | 高 |
| **描述** | 管理员拒绝该教室租借申请并填写拒绝原因 |
| **基本流程** | ① 管理员在详情页点击"拒绝"按钮；② 输入拒绝理由；③ 系统调用 rejectApplication 云函数；④ 校验管理员身份；⑤ 校验申请仍处于待审核状态；⑥ 将申请状态设置为 2（已拒绝），保存拒绝原因 |
| **后置条件** | 申请状态变为"已拒绝"，教室状态矩阵不变 |

### 3.5 数据自动维护

| 项目 | 内容 |
|------|------|
| **需求编号** | FR-010 |
| **名称** | 数据自动维护（定时任务） |
| **优先级** | 中 |
| **描述** | 通过定时云函数 dailyReset 自动执行日常数据维护 |
| **执行逻辑** | **每周六执行**：① 将 nextWeekStatusMatrix 赋值为 thisWeekStatusMatrix；② 将 nextWeekStatusMatrix 重置为 5×13 的零矩阵；**每日执行**：① 将 nextDayStatusMatrix 赋值为 thisDayStatusMatrix；② 将 nextDayStatusMatrix 重置为 13 元素零数组；**持续执行**：① 检查所有已通过(rentalStatus=1)的申请；② 若 rentDate 已过当前日期，将状态更新为 4（已完成） |
| **触发方式** | 微信云开发定时触发器（Timer Trigger） |

## 4. 非功能需求

### 4.1 性能需求

- 页面加载时间：管理面板及列表页的加载时间不超过 2 秒
- 审核操作响应：审核通过/拒绝操作的响应时间不超过 3 秒
- 数据导入性能：批量导入教室/课程/座位数据时，单次操作不超过 10 秒
- 并发处理：系统应能处理多名管理员同时操作的情况，审批时需做并发冲突检测

### 4.2 安全性需求

- 身份验证：所有管理员操作接口必须在云函数端校验用户的管理员身份
- 权限隔离：非管理员用户无法访问任何管理页面和接口
- 并发控制：审批通过操作需校验资源状态，防止并发导致的超卖（双预订）
- 数据校验：所有导入数据需进行基本的格式和完整性校验
- 敏感信息保护：管理人员联系方式等敏感信息仅对审核管理员可见

### 4.3 可用性需求

- 界面简洁清晰，符合微信小程序设计规范
- 审核列表支持按时间倒序排列，最新的申请优先展示
- 审核详情页提供替代教室推荐，辅助管理员决策
- 关键操作（通过/拒绝）需有二次确认机制，防止误操作
- 导入操作需提供进度反馈和结果提示

### 4.4 可维护性需求

- 云函数代码需模块化，权限校验逻辑可复用
- 状态矩阵的轮转由定时任务自动完成，无需人工干预
- 数据导入支持幂等性，可重复执行而不产生重复数据
- 日志记录：关键操作（审批、导入等）需记录操作人和操作时间

| updatedAt | Number | 更新时间戳 |

## 6. 业务流程设计

### 6.1 管理员登录流程

```
开始 → 登录页 Logo 连点3次 → 输入用户ID → 系统查询用户信息
  ├─ 用户不存在 → 提示错误 → 结束
  ├─ 身份非管理员 → 跳转普通用户首页 → 结束
  └─ 身份为管理员 → 跳转管理面板 → 保存全局身份信息 → 结束
```

### 6.2 教室租借审核流程

```
管理员登录 → 管理面板（查看待审数量统计）
  → 进入待审核列表（查看所有 pending 申请）
  → 点击某申请 → 审核详情页（查看完整信息 + 替代推荐）
    ├─ 点击"通过" → 并发冲突检测 → 更新申请状态 + 更新状态矩阵 → 完成
    │     └─ 冲突 → 提示刷新重试
    └─ 点击"拒绝" → 填写拒绝原因 → 更新申请状态 → 完成
```

### 6.3 数据初始化流程

```
管理员登录 → 管理面板 → 进入数据导入页
  ├─ 点击"导入教室" → 批量创建教室文档 + 初始化状态矩阵
  ├─ 点击"导入课程" → 查找对应教室 → 标记课表占用时段（状态=1）
  └─ 点击"导入座位" → 批量创建座位文档 + 初始化状态矩阵
```

### 6.4 每日自动维护流程

```
定时触发 dailyReset 云函数
  ├─ 如果是周六 → 下周矩阵提升为本周矩阵 → 重置下周矩阵
  ├─ 每日执行 → 次日座位矩阵提升为当日矩阵 → 重置次日矩阵
  └─ 每日执行 → 扫描已通过的申请 → 过期的标记为已完成(状态=4)
```

## 7. 界面原型简述

### 管理员登录页
- 输入框：用户ID
- 登录按钮
- 简单的表单验证（非空校验）

### 管理面板（仪表盘）
- 顶部展示当前日期
- 统计卡片：待审核申请数、教室总数
- 功能按钮：审核申请、数据导入

### 待审核申请列表
- 列表视图，每条记录以卡片形式展示
- 卡片内容：申请人、教室、日期、星期、讲次、理由
- 点击卡片跳转至详情页
- 支持下拉刷新

### 审核详情页
- 申请人信息区：姓名、电话、院系
- 申请信息区：教室名、容量、日期、星期、讲次、用途
- 替代推荐区：推荐的替代教室列表（如有）
- 操作区：[通过] 按钮 / [拒绝] 按钮
- 拒绝时弹出输入框填写拒绝原因

### 数据导入页
- 三个导入按钮：导入教室、导入课程、导入座位
- 每个按钮旁显示导入状态提示
- 导入结果反馈（成功/失败详情）

## 8. 风险与约束

| 风险描述 | 影响程度 | 说明 | 应对措施 |
|---------|---------|------|---------|
| 并发审批冲突 | 高 | 多名管理员同时审批同一申请或同一教室的不同申请可能导致数据不一致 | 在审批通过时执行二次冲突检测，检测到冲突时拒绝操作并提示管理员 |
| 数据导入重复 | 中 | 管理员多次点击导入按钮或重复执行导入操作可能导致数据重复 | 在导入时增加幂等性校验，或对已存在的数据进行去重处理 |
| 身份验证遗漏 | 高 | 部分云函数未实现管理员身份校验，存在安全隐患 | 统一审核所有云函数的权限校验逻辑，确保每个管理接口都包含身份验证 |
| 定时任务失效 | 中 | 云函数定时触发器可能因平台原因未按时执行，导致状态矩阵未及时轮转 | 增加手动触发机制作为补充，并记录执行日志用于监控 |
