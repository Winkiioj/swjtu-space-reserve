# 管理员模块开发建议

基于对所有云函数和页面代码的审查，按优先级排列如下。

## P0 — 必须修复（安全/数据正确性）

### 1. approveApplication 缺少管理员身份校验

**位置**：[cloudfunctions/approveApplication/index.js:92-94](f:/TeamWork/swjtu-space-reserve/cloudfunctions/approveApplication/index.js#L92-L94)

**问题**：该云函数明确写着"这里可以根据实际需要添加权限检查"，但实际上没有做任何管理员身份验证。任何知道 applicationID 的人都能调用该接口批准申请。

**修复**：加上 getUserByID 的 admin 校验（其他云函数已实现此模式）：

```js
const admin = await db.collection('Users')
  .where({ userID: approverID, identity: 'admin' }).get()
if (admin.data.length === 0) return { code: 403, message: '无权限', data: null }
```

### 2. 状态矩阵引用共享（所有教室共用同一矩阵对象）

**位置**：[cloudfunctions/importClassrooms/index.js:14](f:/TeamWork/swjtu-space-reserve/cloudfunctions/importClassrooms/index.js#L14)
[cloudfunctions/importSeats/index.js:14](f:/TeamWork/swjtu-space-reserve/cloudfunctions/importSeats/index.js#L14)

**问题**：`const emptyMatrix = Array(5).fill().map(() => Array(13).fill(0))` 看似在创建新矩阵，但在 `for` 循环中 `await` 遇到异步并发时（虽然此处是串行），更大的问题是 **无论是 classrooms 还是 seats 的导入，所有文档都指向同一个矩阵实例吗？**  我们来确认一下：

```js
const emptyMatrix = Array(5).fill().map(() => Array(13).fill(0))
```

这里 `.map()` 确实每次都返回新数组，所以当前代码没有引用共享问题。但写法比较脆弱。如果未来改成：

```js
const emptyMatrix = Array(5).fill(Array(13).fill(0))  // 错误！所有行共享引用
```

就会出现灾难性 bug。建议加固为深拷贝：

```js
function createEmptyMatrix() {
  return Array(5).fill().map(() => Array(13).fill(0))
}
```

### 3. 审批通过逻辑：前端传了 approvedClassroomId 但云函数未使用

**位置**：
- 前端 [review-detail.js:47](f:/TeamWork/swjtu-space-reserve/miniprogram/pages/admin/review-detail/review-detail.js#L47)：获取 `finalClassroomId`，如选择了替代教室就传替代教室 ID
- 前端 [review-detail.js:60](f:/TeamWork/swjtu-space-reserve/miniprogram/pages/admin/review-detail/review-detail.js#L60)：将 `approvedClassroomId` 传给了云函数
- 云函数 [approveApplication/index.js](f:/TeamWork/swjtu-space-reserve/cloudfunctions/approveApplication/index.js)：根本没有接收或处理 `approvedClassroomId`

**问题**：管理员如果选择了替代教室，云函数依然用原教室 `application.classroomApplied` 进行操作。替代推荐功能等于没用。

**修复**：云函数需要接收 `approvedClassroomId` 参数，若存在则用替代教室替代原教室。同时需要处理：
- 检查替代教室在目标讲次是否仍然可用
- 更新替代教室的状态矩阵（而不是原教室）
- 可选：把原教室的申请记录关联到替代教室

## P1 — 重要改进

### 4. getUserByID 查询缺少 limit

**位置**：[cloudfunctions/getUserByID/index.js:9](f:/TeamWork/swjtu-space-reserve/cloudfunctions/getUserByID/index.js#L9)

**问题**：虽然 userID 逻辑上是唯一的，但查询没有加 `.limit(1)`。如果 Users 集合中出现重复 userID，会返回多条数据，而代码只取的 `res.data[0]`，可能取到非预期的记录。

**修复**：

```js
const res = await db.collection('Users').where({ userID }).limit(1).get()
```

---

### 5. importCourses 不更新 nextWeekStatusMatrix

**位置**：[cloudfunctions/importCourses/index.js:20](f:/TeamWork/swjtu-space-reserve/cloudfunctions/importCourses/index.js#L20)

**问题**：课表导入只更新了 `thisWeekStatusMatrix`，`nextWeekStatusMatrix` 保持全零（空闲）。这意味着下周的课表占用信息没有设置，下周的教室状态矩阵在 dailyReset 推进后会出现错误的空闲状态。

**修复**：在遍历课程时，同时更新 `thisWeekStatusMatrix` 和 `nextWeekStatusMatrix`（或者只更新 `nextWeekStatusMatrix`，因为 `thisWeek` 已在教室管理中不可变）。

实际上更好的设计是：课表应该同时写入 `thisWeek` 和 `nextWeek`，或者课表数据独立存储，每次推进矩阵时重新计算。

### 6. dailyReset 没有处理大数据量分页

**位置**：[cloudfunctions/dailyReset/index.js:11](f:/TeamWork/swjtu-space-reserve/cloudfunctions/dailyReset/index.js#L11)

**问题**：`db.collection('Classrooms').get()` 默认最多返回 20 条（微信云函数限制），但这里没有处理分页。如果教室数量超过 20 个，部分教室的状态矩阵不会被轮转。

**修复**：使用 `skip` + `limit` 或 `_.offset` 进行分页查询：

```js
const total = await db.collection('Classrooms').count()
let offset = 0
const limit = 100
while (offset < total) {
  const rooms = await db.collection('Classrooms').skip(offset).limit(limit).get()
  // ...处理...
  offset += limit
}
```

> 注意：微信云数据库 `skip` 性能在大偏移量下较差，但对于教室数量（通常 < 500）足够。

同理，`Seats` 和 `Applications` 集合的查询也需要做分页。

### 7. 所有导入函数没有数据去重/幂等性

**位置**：importClassrooms、importSeats

**问题**：管理员多次点击"导入"按钮，会重复创建相同的教室或座位文档，产生脏数据。

**修复**：导入前先检查 `classroomID` / `seatID` 是否已存在：

```js
const exist = await db.collection('Classrooms')
  .where({ classroomID: room.classroomID }).get()
if (exist.data.length > 0) continue  // 跳过已存在的
```

## P2 — 建议优化

### 8. 提取通用管理员校验中间件

**现状**：6 个云函数各自写着几乎一样的校验代码：

```js
const admin = await db.collection('Users').where({ userID, identity: 'admin' }).get()
if (admin.data.length === 0) return { code: 403, message: '无权限' }
```

建议提取为公共模块 `cloudfunctions/common/auth.js`：

```js
// cloudfunctions/common/auth.js
const cloud = require('wx-server-sdk')
cloud.init()
const db = cloud.database()

async function requireAdmin(userID) {
  if (!userID) return false
  const res = await db.collection('Users').where({ userID, identity: 'admin' }).get()
  return res.data.length > 0
}

module.exports = { requireAdmin }
```

然后在各云函数中：

```js
const { requireAdmin } = require('../common/auth')
if (!await requireAdmin(currentUserID)) return { code: 403, message: '无权限' }
```

### 9. 审核列表后端搜索/筛选/分页

**现状**：`getPendingApplications` 一次性返回所有待审核申请，没有分页参数。随着系统使用，待审核申请数量可能增长，导致加载缓慢。

**改进**：支持 `page` 和 `pageSize` 参数，分页返回。可选支持按教室名称、申请人模糊搜索。

## P3 — 可做可不做

### 13. 审核详情替代推荐支持排序

**现状**：替代教室按容量 ≥ 原教室过滤，但未按容量排序或标记推荐优先级。如果替代教室很多，管理员较难决策。

**建议**：按容量升序排列，容量最接近原教室的排在前面。

### 14. 审核拒绝原因支持预置模板

**现状**：拒绝时需要手动输入。可提供常用拒绝理由选项（如"该教室已满"、"时间段冲突"等），减少输入成本。

### 15. dailyReset 增加异常通知

**现状**：定时任务执行失败没有通知渠道。建议配合微信云开发的日志告警，或执行关键步骤时写日志到单独的 `Logs` 集合。

| **P0** | approveApplication 无 admin 校验 | 任意用户可审批通过申请 |

| **P1** | dailyReset 无分页 | 教室>20个时轮转不全 |
